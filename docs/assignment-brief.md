# Assignment brief (summary)

Source: Greenhouse take-home link (in recruiter email). Summarized, not verbatim.

**Role:** Full Stack Engineer, Education Labs
**Deadline:** Oct 21, 2026, 9:00 AM PT · **Expected effort:** < 1 day, depth over breadth

## Problem framing
1. Users rarely discover or master the full range of AI capabilities.
2. When AI does complex work autonomously, humans become passive observers instead of active learners.

## Choose one
- **Option A — Helping users master Claude.** Integrated, contextual learning (like games teaching
  through play, not tutorials). Assume users already have some Claude experience; focus on growing
  workflow sophistication, not onboarding. Angles: contextual discovery, progressive experimentation,
  progressive challenges, features discoverable at the moment of need.
- **Option B — Learning through collaboration with Claude.** Help users build domain expertise and
  turn AI-assisted work into learning, growing their own capabilities rather than just finishing tasks.

## Deliverables
1. **Deployed, working prototype** the Anthropic team can use; must use the Claude API. Core idea > polish.
2. **Code** in a GitHub repo (quality matters, not primary).
3. **Design rationale** — video (≤ 8 min, screenshare walkthrough) + short written doc covering:
   option chosen & why · design/prototyping process · how it enhances rather than replaces human agency ·
   learning principles · how to measure success · scaling to millions of users · getting a sister team to adopt it.

## Evaluation criteria
Technical execution & iteration · growth-first thinking · user empathy (learners & educators) ·
clear communication · creative problem-solving under ambiguity · scalability thinking.

## AI usage rules
- Using Claude for code and write-ups is encouraged.
- They assess **discernment and judgment in guiding Claude**, not raw output. Mostly-raw Claude output
  without your own perspective will not pass.
- **Must submit complete transcripts** of Claude / Claude Code interactions.

## Tips from the brief
Build on any Claude product · start with one specific user journey · consider different user segments ·
"simple but thoughtful" beats "complex but confusing" · reusing past work is OK if additions are explained.
