## How data is stored and persisted

**There's no login.** On `/co-learn`, the server gives the browser a random anonymous ID in a cookie (`cl_anon`, 60 days, renewed whenever you come back). Everything else is stored in Upstash Redis under that ID.

**A different browser, a private window, or cleared cookies means a brand-new user:** level 1, no past sessions, no learning history. Progress can't follow you to another browser.

**In the same browser, everything is saved, but not forever.** Every record expires 60 days after it was last touched, and the clock resets when you use it:
- **Your profile:** XP, level, unlocks, settings, and a per-concept mastery score. This is renewed every time you're active.
- **Each session:** the full conversation with Claude, the chat history you see, every question with your answers and grades, bosses, and story chapters. Each session expires 60 days after its own last activity.

**What Claude remembers:**
- **Within a session:** Claude gets the whole conversation on every turn.
- **Across sessions:** Claude does *not* see your earlier conversations. Only XP, unlocks, settings, and the mastery scores carry over. Mastery changes how hard questions are and which concepts count as already learned.

**On Anthropic's side:** the code sandbox expires after a while idle; the app then starts a new one and re-uploads the demo CSV. Charts are stored with Anthropic and shown only to the session that made them.

Your local dev server uses the same Redis database as the live site.

"Reveal" is the moment the app shows the correct answer to *this* question. That means the best option highlighted, or an explanation that states the answer. Hints and lessons can teach the idea, but they stop short of that.

Here's where each path leads today:

| What you do | What you see |
|---|---|
| Answer correctly | Confirmation and why (revealed) |
| Partly right | The missing piece is named (revealed) |
| Answer wrong | Only a hint, then the options |
| Pick an option | Best option highlighted, with a reason for every option (revealed) |
| Skip | Nothing on the card, but Claude makes the call in the chat and says why, so it's revealed there anyway |
| Quiz me later | Nothing until the wrap-up |

**Your rule** means hints, "Teach me", and the Ask box never state the answer before one of the revealed rows above has happened.

**Follow-up for 11:** you said to decline "just tell me" only once. So what happens the second time? My recommendation:
- **Second ask:** Claude gives the answer and the question closes as "revealed".
- **Credit for a revealed question:** no mastery credit and no XP. The concept is marked for review, with kind copy ("Got it, this one will come back for a quick review later.").
- **Scope:** the decline happens once per question, not once per session.

**Related:** after Skip, the card could show a small "See the answer" link. You've chosen to move on, so showing it doesn't undercut a later attempt. I recommend yes.

## 12. What the "guard" is about

The help tools need to see the answer key so they teach the *right* idea. The risk is that a hint or lesson gives the answer away by accident. For example: "Hint: think about why flagging *more* customers would help when offers are cheap." That basically answers the threshold question.

There are three ways to guard against it:
1. **Instructions + my testing:** tell Claude not to give away the answer, then deliberately try to trick it before shipping ("just tell me", "is it A?", "what would you pick?"). No added delay.
2. **A second check on every help reply:** a fast model reads each reply and rewrites it if it leaks. This is safer but adds about a second and a small cost per reply.
3. **Don't show the help tools the answer key:** this can't leak, but the help gets vaguer and could teach something slightly off.

**My recommendation:** option 1. Your "decline only once" rule already lowers the stakes, since a learner who really wants the answer gets it on the second ask.

## 6. Getting through bosses (or skipping them)

Today, getting past a boss means skipping all 2–3 questions one at a time. Then there's a ~20-second wait for the story chapter before the work resumes. That's clunky if you just want to work.

My proposal has two exits:
1. **Opt in before the wait.** When a boss is due, show a small card: "A boss approaches! Take it on (about 2 minutes) or keep working." Nothing gets generated until you choose to fight, so "keep working" means no 24-second wait and no cost.
2. **"Skip this boss" during the fight.** A quiet link on the boss card closes all remaining questions in one click. The work resumes immediately, with no story wait.

| Aspect | Behavior |

| Effect | No XP, no story chapter; the boss's concepts are marked for review |

## Learning history with the current system

  - **Leftover work framing:** the intent screen asks "What are you working on?", and Claude still has the coding sandbox.
  - **Facts aren't grounded in sources.** That matters more for history than for a model trained on your own data.

## Extending it: a "Learn" mode

One way to do it is to add a second mode that reuses about 90% of the system: the same question cards, pacing engine, help tools, bosses, story, XP, Codex and review. In practice it would be a reworked version of the archived Learning Quest, built on Co-learn instead of as a separate app. Only five pieces would change:

1. **A mode choice at intent.** "Get something done" or "Learn a topic", guessed from how you phrase the goal and easy to switch.
2. **A short learning path instead of work milestones.** The background step that already sketches milestones would plan 4–6 chapters, e.g. "Founding → Conquest of Italy → Punic Wars → Crisis → Fall". You'd see it as a slim progress strip and could pick or reorder chapters, which keeps you the decision-maker. Each chapter ends at a milestone, so the boss becomes a chapter test.
3. **A tutor prompt instead of the work prompt.** Claude teaches in short chunks (about 120 words), then asks a question each time. The question types map naturally:

   | Type | In history |
   |---|---|
   | Decide | "Choose where we go next" or "take a position" ("Was Caesar a reformer or a tyrant? Argue it.") |
   | Predict | "What do you think happened next?" (very effective for history) |
   | Spot the issue | "Spot the myth or anachronism" |
   | Explain back / fill the gap | Unchanged |

5. **Pacing by mode.** In Learn mode questions come after every chunk rather than only at rare high-value moments. Difficulty bands, mastery and review stay exactly as they are.
